# پنل هوش مصنوعی movim

پنل **AI Panel** در نصب‌کنندهٔ اصلی movim قرار دارد. کد، تست‌ها و نسخهٔ ثابت Pi در پوشهٔ `ai/` مخزن هستند. فایل‌های نصبی از بخش Releases دانلود می‌شوند:

- [نصب ویندوز movim](https://github.com/moeinparvizi/movim/releases/latest/download/movim-Setup.exe)
- [بستهٔ مک movim](https://github.com/moeinparvizi/movim/releases/latest/download/movim-macOS.zip)
- [اثر انگشت فایل‌ها](https://github.com/moeinparvizi/movim/releases/latest/download/SHA256SUMS)

## نصب و تنظیم مدل

در ویندوز، movim در `%LOCALAPPDATA%/Programs/movim` نصب می‌شود. Node، Neovim و Pi همراه نصب‌کننده‌اند.

در مک، کل ZIP را استخراج و `Install.command` را اجرا کنید. دریافت وابستگی‌ها و Pi به اینترنت نیاز دارد. فرمان اجرا `movim` است. نصب تعاملی کامل روی مک در این محیط ویندوزی قابل آزمایش نیست؛ تست‌های بدون رابط روی مک در CI اجرا می‌شوند.

فرمان `:AIConfigure` آدرس API سازگار با OpenAI، شناسهٔ دقیق مدل، سقف واقعی Context و **نام متغیر محیطی کلید** را می‌گیرد. خود کلید را در این فرم وارد نکنید. متغیر پیش‌فرض `MOVIM_AI_API_KEY` است. اگر کلید تنظیم نشده باشد، پس از فرم تنظیمات یک ورودی مخفی برای خود کلید باز می‌شود. با فرمان `:AIKey` نیز می‌توانید وقتی درخواستی در حال اجرا نیست، کلید را بدون راه‌اندازی مجدد وارد یا عوض کنید. کلید فقط در محیط پردازش همین جلسه می‌ماند و در فایل تنظیمات یا تاریخچهٔ فرمان ذخیره نمی‌شود؛ بعد از خروج باید دوباره واردش کنید، یا متغیر محیطی را پیش از اجرای برنامه تنظیم کنید. هیچ حساب یا کلید API داخل نصب‌کننده قرار ندارد. دسترسی به مدل‌های GapCode از طریق این پنل فقط وقتی ممکن است که ارائه‌دهندهٔ شما آن مدل را با API و مجوز شما در دسترس قرار دهد.

## کار با پنل و تب‌ها

| کار | میان‌بر یا فرمان |
|---|---|
| باز و بسته کردن پنل | `Space aa` یا `:AIPanel` |
| ارسال انتخاب برای پیشنهاد تغییر در تب جدید | در Visual، `Space ae` |
| پیوست بافر فعال | `Space af` یا `:AIAttach` |
| پیوست به تب جدید | `:AIAttach!` |
| پیوست فایل انتخابی | `:AIFile path`؛ با `!` در تب جدید |
| نوشتن پیام | `:AIChat` |
| ساخت، انتخاب، تغییر نام، بستن تب | `:AINew`، `:AISelect`، `:AIRename`، `:AICloseTab` |
| لغو درخواست | `:AICancel` |
| تازه‌کردن یا حذف پیوست | `:AIRefresh`، `:AIRemove` |
| دیدن Diff | `:AIPreview` |
| اعمال، رد، درخواست اصلاح | `:AIApply`، `:AIReject`، `:AIRevise` |
| برگشت به منبع برای انتخاب مجدد | `:AIRerun` سپس Visual و `Space ae` |
| تغییر سمت | `:AIMove left`، `right`، `top`، `bottom` |
| تغییر اندازه | `:AIResize 60` |

داخل پنل، کلیدهای `i` پیام، `n` تب جدید، `t` انتخاب تب، `r` تغییر نام، `x` بستن تب، `Ctrl-C` لغو، `d` پیش‌نمایش، `a` اعمال، `R` رد و `q` مخفی کردن هستند. در تنظیمات مورداعتماد Lua، مقادیر `vim.g.movim_ai.keys` و `panel_keys` قابل تغییرند؛ مقدار `false` یک میان‌بر را غیرفعال می‌کند.

هر تب پردازش مستقل Pi، تاریخچه و پیوست‌های خودش را دارد. تب پنل، tabpage ادیتور نیست. مخفی کردن پنل تاریخچه یا درخواست را پاک نمی‌کند. بستن تب فعال ابتدا انتخاب «ادامه» یا «لغو و بستن» را نشان می‌دهد. تاریخچه فقط تا خروج از برنامه باقی می‌ماند. بعد از لغو، پردازش Pi متوقف می‌شود؛ متن گفت‌وگو دیده می‌شود اما درخواست بعدی یک نشست تازهٔ مدل دارد.

## پیشنهاد، تأیید و Undo

۱. متن را به شکل کاراکتری یا خطی انتخاب کنید؛ انتخاب بلوکی در این نسخه پشتیبانی نمی‌شود و صریحاً رد می‌شود.

۲. `Space ae` را بزنید و پرامپت را تأیید کنید. لغو ورودی هیچ درخواستی نمی‌فرستد. یک تب جدید برای تسک ساخته می‌شود.

۳. کل محتوای بافر، شامل تغییرات ذخیره‌نشده، همراه مسیر، زبان، نسخه و محدودهٔ انتخاب به‌عنوان Context فرستاده می‌شود. نام و نسخهٔ پیوست‌ها در پنل دیده می‌شوند. مدل فقط برای همان انتخاب پیشنهاد می‌دهد.

۴. پاسخ معتبر در وضعیت `review` قرار می‌گیرد. با `:AIPreview` تفاوت متن اصلی و پیشنهاد را ببینید. تا این مرحله بافر و فایل تغییر نمی‌کنند.

۵. `:AIApply` فقط انتخاب اولیه را جایگزین می‌کند؛ فایل خودکار ذخیره نمی‌شود و یک Undo کل اعمال را برمی‌گرداند. `:AIReject` هیچ تغییری نمی‌دهد. اعمال دوبارهٔ همان پیشنهاد ممنوع است.

اگر بافر در حین انتظار تغییر کند، حتی پس از Undo تغییر خودتان، Apply مسدود می‌شود. از `:AIRerun` به فایل برگردید، محدوده را دوباره انتخاب کنید و درخواست تازه بدهید. شمارهٔ خط قدیمی خودکار به محل جدید نگاشت نمی‌شود. نتیجهٔ اعمال یا رد به گفت‌وگوی بعدی منتقل می‌شود.

## Context و فایل‌های حساس

فایل باز از محتوای بافر خوانده می‌شود؛ فایل بسته از دیسک در بافر بارگذاری می‌شود. پیوست قدیمی پیش از ارسال دوباره تشخیص داده می‌شود؛ با `:AIRefresh` نسخهٔ تازه را انتخاب کنید.

برآورد اندازه عمداً محافظه‌کارانه است: بایت‌های UTF-8، تاریخچه، سربار و فضای خروجی محاسبه می‌شوند. اگر Context جا نشود، درخواست متوقف می‌شود؛ چیزی بی‌صدا حذف نمی‌شود. پیوست‌ها را حذف کنید، تب تازه بسازید یا مدل با ظرفیت واقعی بیشتر تنظیم کنید. محتوای فایل فعال به شکل خودکار ناقص نمی‌شود.

مسیرهای معمول `.env`، کلید خصوصی، SSH و فایل‌های credential/secret پیش‌فرض مسدودند. `sensitive_patterns` قابل تنظیم است. `sensitive_policy='allow'` فقط بعد از بررسی آگاهانهٔ اطلاعات ارسالی استفاده شود. این سیاست بر پایهٔ مسیر است و تشخیص جامع رازها داخل هر فایل نیست.

## اتصال و تست

Pi نسخهٔ ثابت `0.73.1` با RPC رسمی JSONL استفاده می‌شود. تمام ابزارها و کشف خودکار extension، skill، قالب پرامپت و فایل‌های دستور پروژه خاموش‌اند. پوشهٔ کاری و تنظیمات Pi برای هر تب مستقل و خالی است. اجرای فرمان، تست پروژه یا تغییر فایل توسط مدل در این MVP وجود ندارد.

قرارداد پیشنهاد دقیقاً شامل `requestId`، `snapshotId`، `replacementText` و `explanation` است. پاسخ ناقص، شناسهٔ اشتباه، خطای شبکه یا خروجی دیررسِ لغوشده قابل اعمال نیست.

تست‌های خودکار با Adapter جعلی و همچنین Pi واقعی متصل به سرویس HTTP آزمایشی محلی اجرا می‌شوند؛ این‌ها نیازی به API پولی ندارند و کیفیت مدل آنلاین را تضمین نمی‌کنند. بازبینی و اجرای مستقل تست‌ها با Luna هم انجام شده است. ویرایش چندفایلی، پذیرش بخشی از Diff و Context پیشرفتهٔ LSP در این MVP نیستند.
