# پنل تسک‌های پروژه

پنل با نام پروژه و راهنمای کوتاه کلیدها باز می‌شود و اولین تسک آمادهٔ انتخاب است. وضعیت اجرا، موفقیت و خطا رنگ جدا دارند. با `/` یک پاپ‌آپ وسط صفحه باز کنید، نام تسک را جست‌وجو کنید و با `Enter` اجرا کنید؛ `Esc` بدون اجرا آن را می‌بندد.

خروجی تسک در یک پنجرهٔ ترمینال جدا باز می‌شود و بافر خالی `[No Name]` به فهرست فایل‌های باز اضافه نمی‌کند. بازکردن دوبارهٔ خروجی تسکِ در حال اجرا همان ترمینال را نشان می‌دهد.

پروژه را باز کنید و `Space`، سپس `r` و `t` را بزنید؛ یا دستور `:Tasks` را وارد کنید. پنل پایین صفحه تسک‌های `.vscode/tasks.json` و اسکریپت‌های `package.json` را نشان می‌دهد. پس از اجرا، فهرست در سمت راست و خروجی ترمینال در سمت چپ همین پنل قرار می‌گیرد. برای اجرا روی نام تسک `Enter` بزنید یا روی آن دوبار کلیک کنید. هر تسک ترمینال خودش را دارد و می‌توانید چند تسک را هم‌زمان اجرا کنید.

| کلید در پنل | کار |
|---|---|
| `Enter` | اجرای تسک انتخاب‌شده؛ اگر در حال اجرا باشد، نمایش خروجی |
| `o` | نمایش مجدد خروجی تسک انتخاب‌شده |
| `x` | توقف تسک انتخاب‌شده |
| `r` | خواندن دوبارهٔ فایل‌ها |
| `e` | باز کردن یا ساخت `.vscode/tasks.json` |
| `c` | اجرای یک دستور دلخواه در پوشهٔ پروژه |
| `q` | پنهان‌کردن فهرست و خروجی، بدون توقف تسک‌ها؛ برای نمایش دوباره خروجی `o` را بزنید |

برای برگشت از حالت تایپ در ترمینال `Ctrl+\` و سپس `Ctrl+n` را بزنید. وضعیت اجرای هر تسک کنار نام آن نمایش داده می‌شود. پس از ذخیرهٔ `tasks.json` یا `package.json` پنل به‌روزرسانی می‌شود.

برای تعریف یک دستور، کلید `e` را بزنید و فایل را ذخیره کنید. نمونه:

```jsonc
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Run development server",
      "type": "shell",
      "command": "npm run dev",
      "options": { "cwd": "${workspaceFolder}" }
    }
  ]
}
```

تسک‌های `shell`، `process` و `npm`، آرگومان‌های رشته‌ای، پوشهٔ کاری، متغیرهای محیطی، تنظیمات جداگانهٔ `windows`، `osx` و `linux`، کامنت و ویرگول پایانی JSONC پشتیبانی می‌شوند. متغیرهای `${workspaceFolder}`، `${workspaceFolderBasename}`، `${file}`، `${fileDirname}`، `${fileBasename}` و `${env:NAME}` قابل استفاده‌اند. فایل جاری همان فایلی است که هنگام باز کردن پنل فعال بوده است.

اسکریپت‌های npm با توجه به `packageManager` یا فایل قفل پروژه با npm، pnpm، yarn یا bun اجرا می‌شوند؛ ابزار انتخاب‌شده باید نصب و در PATH باشد. همهٔ قابلیت‌های VS Code پیاده‌سازی نشده‌اند: تسک‌های دارای `dependsOn`، پوستهٔ سفارشی `options.shell`، ورودی‌های تعاملی و انواع افزونه‌ای اجرا نمی‌شوند و برایشان خطا نمایش داده می‌شود؛ problem matcher و تنظیمات presentation نیز اعمال نمی‌شوند.
## Services و Database

با `:Services` یا `Space r S` سرویس‌های پروژه را کنار تسک‌های VS Code و اسکریپت‌های package.json ببینید. Enter سرویس را اجرا می‌کند، `o` خروجی را نشان می‌دهد، `x` متوقف می‌کند و `e` تنظیمات را در `.movim/services.json` باز می‌کند. بستن پنل سرویس را متوقف نمی‌کند.

با `:Database` یا `Space r D` فهرست اتصال‌ها را باز کنید. برای شروع، `a` بزنید، SQLite را انتخاب کنید و نام و مسیر فایل را تأیید کنید. مسیر نسبی از پوشهٔ پروژه محاسبه می‌شود. SQLite از Node.js نسخهٔ 22.23.5 یا جدیدتر با ماژول node:sqlite استفاده می‌کند.

روی یک اتصال، `s` جدول‌ها یا اشیای دیتابیس را نشان می‌دهد. Enter ویرایشگر کوئری را باز می‌کند. مثلاً `SELECT 42 AS answer;` بنویسید و در حالت Normal با F5 یا Ctrl+Enter اجرا کنید. با `q` نتیجه را ببندید. هر اجرا یک نشست مستقل است؛ SQLite در هر اجرا یک دستور می‌پذیرد.

برای PostgreSQL، MySQL، MariaDB، SQL Server، MongoDB، Redis و ODBC کلاینت مربوط باید در PATH باشد. ODBC به isql و یک DSN نیاز دارد. احراز هویت غیرتعاملی را در کلاینت تنظیم کنید. اتصال‌ها در `.movim/databases.json` ذخیره می‌شوند؛ با `e` ویرایش و با `r` بازخوانی کنید.

برای موتورهای دیگر، Custom را انتخاب کنید. اولین عضو آرایه مسیر برنامه و بقیه آرگومان‌های آن هستند؛ مثلاً `["sqlite3","local.db"]`. کلاینت یا برنامهٔ واسط باید دستور را از ورودی استاندارد بخواند و نتیجه را چاپ کند. برای فعال کردن `s` در این مثال، فیلد `"schema": ".tables"` را به اتصال اضافه کنید.
