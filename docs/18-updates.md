# به‌روزرسانی movim

پس از اعمال آپدیت، فایل شروع جدید همان بار اجرا می‌شود؛ امکاناتی که در راه‌اندازی اضافه شده‌اند هم با بازکردن برنامه فعال می‌شوند. روی دیسک کند، عملیات نوشتن با محدودیت زمانی قطع نمی‌شود.

حتی فایل‌های موقت شخصی کنار کانفیگ حفظ می‌شوند؛ آپدیت فایل موقت خودش را با نام یکتا می‌سازد. اگر اطلاعات بازیابی خراب باشد، جایگزینی متوقف می‌شود و بکاپ برای بررسی باقی می‌ماند.

نصب Node.js باید npm را هم داشته باشد تا در صورت تغییر وابستگی Pi، آماده‌سازی آن روی ویندوز، مک و لینوکس انجام شود.

فایل‌ها یک بار هنگام دریافت و بار دیگر قبل از اعمال بررسی می‌شوند؛ تغییر دستی پس از دانلود هم بدون اخطار جایگزین نمی‌شود. در نصب‌کننده نیز بررسی پیش از کپی فایل‌ها انجام می‌شود.

برای دریافت امکانات جدید، در داشبورد **u**، در محیط ویرایش **Space u U**، یا دستور **`:MovimUpdate`** را بزنید. آخرین نسخهٔ پایدار GitHub در پس‌زمینه دانلود می‌شود؛ پس از پیام آماده‌بودن، همهٔ پنجره‌های movim را ببندید و دوباره باز کنید. لازم نیست برنامه را حذف کنید. برای خروج همراه با ثبت پیش‌نویس‌ها و فضای کاری از **Space qq** استفاده کنید.

آپدیت به Node.js و اینترنت نیاز دارد؛ Node در نصب‌کنندهٔ ویندوز همراه برنامه است. دانلود پیش از اعمال با SHA256SUMS و سپس هش تک‌تک فایل‌های release.json بررسی می‌شود. فقط فایل‌های توزیع‌شدهٔ کانفیگ، امکانات و مستندات جایگزین می‌شوند. در نسخهٔ AI، کد AI نیز با همان نسخه به‌روز می‌شود؛ اگر وابستگی Pi تغییر کند، ابتدا در پوشهٔ موقت با npm آماده می‌شود. شکست دانلود یا آماده‌سازی، نسخهٔ نصب‌شده را تغییر نمی‌دهد.

پروژه‌ها، فایل‌های کاری، پیش‌نویس‌ها، تاریخچهٔ جست‌وجو، excludeها، اندازهٔ پنجره‌ها، تم ذخیره‌شده، داده‌های AI و کلیدهای API خارج از فهرست آپدیت هستند و حذف نمی‌شوند. تغییر فایل‌های اصلی روی دیسک همچنان به `:w` نیاز دارد؛ پیش‌نویس ورک‌اسپیس جای ذخیرهٔ فایل نیست.

برای تنظیمات شخصی یک فایل **user.lua** کنار init.lua بسازید. این فایل پس از کانفیگ اصلی بارگذاری می‌شود و آپدیت آن را تغییر نمی‌دهد. نمونه:

```lua
vim.opt.number = true
vim.opt.relativenumber = false
```

اگر یکی از فایل‌های اصلی مثل lua/config/options.lua را دستی تغییر داده باشید، آپدیت پیش از جایگزینی متوقف می‌شود و نام فایل را نشان می‌دهد. تغییر دلخواه را به user.lua منتقل کنید و نسخهٔ اصلی آن فایل را برگردانید؛ سپس آپدیت را دوباره بزنید. فایل شخصی‌ای که با نام یکی از فایل‌های تازهٔ برنامه تداخل داشته باشد هم جایگزین نمی‌شود. در checkout گیت از Git برای دریافت تغییرات استفاده کنید؛ آپدیت داخل برنامه روی سورس اجرا نمی‌شود.

در اجرای بعد، فایل‌های بررسی‌شده همراه با بکاپ در **.movim-update/backups/** اعمال می‌شوند. اگر نوشتن شکست بخورد، فایل‌های قبلی بازگردانده می‌شوند؛ قطع برق یا بسته‌شدن فرایند وسط نصب در اجرای بعد بازیابی می‌شود. بکاپ‌ها خودکار حذف نمی‌شوند؛ بعد از اطمینان از نسخهٔ جدید می‌توانید بکاپ‌های قدیمی را دستی پاک کنید. برای بازگردانی دستی، movim را ببندید و فایل‌های بکاپ نسخهٔ موردنظر را برگردانید.

اگر lazy-lock.json تغییر کرده باشد، پلاگین‌ها پس از اجرا با نسخه‌های همان انتشار هماهنگ می‌شوند. این مرحله اینترنت و Git می‌خواهد؛ اگر شکست بخورد، `:MovimUpdate` آن را دوباره انجام می‌دهد. اگر پلاگین بارگذاری‌شده تغییر کرد، یک بار دیگر برنامه را باز کنید. باینری Neovim، ابزارهای زبان و launcher با این آپدیت سبک جایگزین نمی‌شوند؛ برای ارتقای آن‌ها نصب‌کنندهٔ جدید را روی نصب فعلی اجرا کنید، بدون uninstall. نصب‌کننده‌های جدید ویندوز فایل‌های کانفیگ را قبل از ارتقا بررسی و بکاپ می‌کنند؛ نصب‌کننده‌های مک و لینوکس نیز برای نصب‌های دارای release.json از همین مسیر حفظ فایل‌ها استفاده می‌کنند.

نصب‌های معمولی قدیمی برای دریافت بخش AI یکپارچه به نصب‌کنندهٔ جدید نیاز دارند. قبل از نصب همهٔ پنجره‌ها را ببندید و مسیر نصب فعلی movim را انتخاب کنید. برنامه و داده‌هایش را حذف نکنید. پس از آن، آپدیت امکانات از داخل برنامه در دسترس است.

movim روزی یک بار نسخهٔ پایدار جدید را بررسی و پیشنهاد می‌کند؛ دانلود و نصب بدون زدن دکمه شروع نمی‌شود. برای بررسی دستی `:MovimCheckUpdate` را بزنید. بررسی اعلان به curl نیاز دارد؛ دریافت آپدیت از Node استفاده می‌کند. برای غیرفعال‌کردن بررسی روزانه، در user.lua بنویسید `vim.g.movim_check_updates = false`. نسخه‌های پیش‌نمایش پیشنهاد نمی‌شوند.
