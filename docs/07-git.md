# فصل ۷ — گیت کامل (قلب این کانفیگ)

این فصل مهم‌ترین تفاوت این کانفیگ با بقیه است: **چرخه کامل گیت بدون ترک ادیتور**، دقیقاً با عادت‌های WebStorm.

## نقشه کلی

وقتی ورک‌اسپیس شامل چند مخزن باشد، بازکردن Git با `Space gg` (lazygit)، `Space gd` (Diffview)، `Space ge` (درخت وضعیت) و `Space gu/gL/gb` (جستجوگرهای Git) ابتدا می‌پرسد کدام پروژه را می‌خواهید. انتخاب مخزن مسیر کاری ورک‌اسپیس را عوض نمی‌کند؛ لغو انتخاب چیزی را باز نمی‌کند. اگر فقط یک مخزن پیدا شود مستقیم باز می‌شود. `Space gc` همچنان ثبت کامیت است.

مخزن والد، مخزن فایل جاری و مخزن‌های زیرپوشه‌ها تا عمق سه شناسایی می‌شوند. پوشه‌های وابستگی و خروجی مانند `node_modules`، `vendor`، `dist` و `build` اسکن نمی‌شوند؛ اسکن حداکثر ۳۰۰۰ پوشه دارد. برای پروژهٔ عمیق‌تر، همان پوشه را به‌عنوان ورک‌اسپیس باز کنید.

اعتبارسنجی مخزن در پس‌زمینه انجام می‌شود تا هنگام پاسخ‌دادن Git بتوانید با ادیتور کار کنید. خطای Git نمایش داده می‌شود؛ اگر حین بررسی ورک‌اسپیس را عوض کنید، نتیجهٔ انتخاب قبلی باز نمی‌شود.

## پول هوشمند — همان Ctrl+T

وقتی `<leader>gp` یا `:Gpull` را می‌زنید، ابتدا ریموت را انتخاب کنید (اگر فقط یکی باشد خودکار انتخاب می‌شود)، سپس برنچ مبدأ را از فهرست به‌روز سرور انتخاب کنید. برنچ فعلی عوض نمی‌شود. پس از انتخاب، Git با `pull --no-rebase --autostash` تغییرات مبدأ را در برنچ فعلی مرج می‌کند و تلاش می‌کند تغییرات محلی tracked را دوباره برگرداند. فایل‌های ذخیره‌نشدهٔ داخل ادیتور را ابتدا خودتان ذخیره کنید؛ ابزار آنها را خودکار ذخیره نمی‌کند. فایل‌های untracked در autostash قرار نمی‌گیرند و اگر با فایل دریافتی تداخل داشته باشند ممکن است Git عملیات را متوقف کند.

فهرست برنچ‌ها و pull نیاز به دسترسی به ریموت دارند. برای ریموت خصوصی، احراز هویت Git را از قبل تنظیم کنید. با لغو انتخاب، pull انجام نمی‌شود. در صورت کانفلیکت، Diffview باز می‌شود.

## کانفلیکت‌ریزولوشن (دقیقاً عین Ctrl+T وب‌استورم)

وقتی کانفلیکت رخ داد، Diffview باز می‌شود:

1. در پنل فایل‌ها، فایل کانفلیکت‌دار را انتخاب و با `Enter` باز کنید.
2. در مرج معمولی، سمت چپ نسخهٔ برنچ فعلی (**ours**) است، وسط نتیجهٔ قابل ویرایش و سمت راست نسخهٔ برنچ دریافتی (**theirs**).
3. کرسر را روی بخش دارای کانفلیکت در پنجرهٔ وسط ببرید و یکی از گزینه‌ها را انتخاب کنید:

| کلید | کار |
|---|---|
| `]x` / `[x` | پرش به کانفلیکت بعدی/قبلی |
| `Space cm` | بازکردن منوی انتخاب سمت چپ یا راست |
| `Space co` | انتخاب سمت چپ (ours) |
| `Space ct` | انتخاب سمت راست (theirs) |
| `Space ca` | نگه‌داشتن هر دو سمت |
| `]x` / `[x` | پرش بین بخش‌های کانفلیکت |

4. بعد از حل تمام بخش‌های هر فایل، فایل را ذخیره کنید. در پنل فایل‌های Diffview روی آن `-` بزنید تا stage شود. بعد از stage شدن همهٔ فایل‌های درگیر، `:Gcontinue` مرج را تکمیل می‌کند. `:Gabort` مرج یا rebase در جریان را لغو می‌کند.

اگر کانفلیکت هنگام بازگرداندن autostash رخ دهد، معنی دو سمت فرق دارد: چپ نتیجهٔ مرج و راست تغییرات محلی ذخیره‌شده است. در این حالت ممکن است مرج تمام شده باشد و stash نگه داشته شود؛ پس از حل و stage فایل‌ها با `git stash list` آن را بررسی کنید و فقط پس از اطمینان خودتان حذفش کنید. در یک rebase نیز سمت‌ها نسبت به مرج عادی جابه‌جا هستند؛ پیام movim نوع عملیات را نشان می‌دهد.

## کامیت

| کلید | کار |
|---|---|
| `<leader>gc` | کامیت تغییرات staged (پنجره پیام باز می‌شود) |
| `<leader>gC` | اول همه (شامل untracked) stage می‌شود، بعد کامیت |
| `<leader>ga` | stage کل فایل جاری |
| `<leader>ghs` | stage فقط hunk (بخش تغییر) جاری / انتخابی |
| `<leader>ghu` | undo آخرین stage |

## پوش

| کلید | کار |
|---|---|
| `<leader>gP` | push (اگر upstream نبود خودش set می‌کند) |

## Stash — Shelve/Unshelve وب‌استورم

| کلید | کار |
|---|---|
| `<leader>gS` | stash (شامل فایل‌های untracked، با پیام زمان‌دار) |
| `<leader>gs` | برگرداندن آخرین stash و حذفش |

## lazygit — UI کامل گیت

`<leader>gg` → ترمینال شناور lazygit (واقعاً به آن نیاز پیدا می‌کنید برای history، cherry-pick، rebase تعاملی و...):

- `space` stage/unstage فایل یا hunk — **unversioned files هم اینجا نشان داده می‌شوند**
- `c` کامیت، `P` push، `p` pull
- `b` برنچ‌ها: `space` سوییچ، `n` برنچ جدید
- `enter` روی کامیت = diff، `s` squash، `r` reword
- `?` راهنما، `q` خروج

## دیدن تغییرات و تاریخچه

| کلید | کار |
|---|---|
| `<leader>gd` | Diffview: وضعیت کل پروژه + diff هر فایل |
| `<leader>gf` | تاریخچه فایل جاری (هر کامیت با diff) |
| `<leader>gF` | تاریخچه کل ریپو |
| `<leader>gb` | inline blame (معلق کردن نویسنده/تاریخ روی خط) |
| `<leader>ghb` | blame کامل خط جاری (پاپ‌آپ) |
| `<leader>gu` | لیست فایل‌های changed/unversioned (telescope) |
| `<leader>ge` | همان به شکل اکپلورر شناور |

## Gutter (کنار کد) — مثل نوار آبی/سبز وب‌استورم

- `▎` سبز = خط اضافه، نارنجی = تغییر، `▁` قرمز = حذف
- `]h` / `[h` = پرش بین تغییرات فایل
- `<leader>ghp` = پیش‌نمایش inline تغییر
- `<leader>ghr` = برگرداندن همان بخش (reset hunk)
- `ih` = انتخاب hunk به شکل text object (مثلاً `dih`)
